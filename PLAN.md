# Money Graph — актуальная приёмка перед сдачей

Текущий продукт: локальный pipeline и Streamlit-интерфейс на официальном наборе, отдельные HTTP API и worker. Старые расписания T+ и ожидание поставки Lane A отменены. Основная инструкция — [README](README.md), формулы — [методология](docs/methodology.md), порядок показа — [демо](docs/demo.md).

## Подтверждено

- Расчёт охватывает 2 248 клиентов, 3 119 связей, 4 840 транзакций; 105 кластеров, 35 компонент, 19 изолятов, Top-20.
- Все шесть ролей представлены. Seed исключены из transit, depth=4 — из terminal.
- Есть публикация с SHA256, независимый validator, Docker и локальные команды Windows/Linux/macOS.
- UI объединяет очередь и карточку в «Проверке клиентов»; отдельный раздел — «Сеть и сообщества». Граф локальный SVG/JavaScript.
- В разделе сети есть read-only симуляция исключения top-1/3/5/10 по приоритету против оборота: связность оставшихся клиентов, новые изоляты и исторические суммы. Метод и ограничения — в [методологии](docs/methodology.md#устойчивость-сети-what-if).
- Факты всех 2 248 evidence и 20 why проверены [отдельным аудитом](docs/evidence-audit.md).
- Реализованы [локальный API и worker](docs/backend.md): импорт официальных файлов, очередь расчётов, чтение аналитики, сохранённый выбор и CSV. Streamlit использует прежний прямой доступ к bundle.
- Существуют [исторические отчёты QA](docs/README.md); их runtime и число тестов относятся к указанным там версиям.

## Что проверить на финальном commit

1. Проверить `git status`: локальный `outputs/current.json` может указывать на запуск, отсутствующий в Git. Для сдачи нужны указатель и полный соответствующий каталог, либо воспроизводимый пересчёт.
2. На машине показа выполнить `make run` / `.\make.cmd run` или Docker-последовательность из README.
3. Выполнить validator, полный pytest и аудит evidence по [QA-протоколу](docs/qa.md).
4. Проверить на живом UI произвольные gid, прямые связи, 2-hop, boundary, изолят и скачивание CSV. Автотесты не заменяют репетицию с человеком.
5. Провести две репетиции до пяти минут; три произвольных gid объяснить за минуту.
6. Проверить доступ жюри к приватному репозиторию и наличие исходных Parquet. Убедиться, что сдаваемый результат проходит SHA256 после клонирования.

**Открытый локальный вопрос:** старый запуск `00e4ed69-15c5-4c87-b3cb-ea4a1e44ac57` при последней проверке рабочей копии не прошёл SHA256. Текущий пересчитанный запуск проходит. Проверка доставки и пересчёт на машине показа обязательны; ручная смена хешей не является исправлением.

## Критерии оценки

| Критерий | Вес | Доказательство |
| --- | ---: | --- |
| Соответствие и работоспособность | 25 | Pipeline, 3 CSV, роли/кластеры всех клиентов, UI и произвольный gid |
| Техническая реализация | 25 | Тесты, сверка входа, SHA256, повторяемость, обработка неполноты |
| README и воспроизводимость | 25 | Установка, команды, схема, формулы/пороги, ограничения и план масштабирования |
| Ценность и применимость | 15 | Понятное why, очередь проверки и разбор связей |
| Потенциал и оригинальность | 10 | Учёт границы наблюдения, объяснимость и обоснованные направления развития |

Это рабочая матрица команды, а не выставленная жюри оценка.

## Отложено
