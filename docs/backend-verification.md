## Негативные и конкурентные сценарии

- Неизвестные query-параметры, повторы одиночных параметров, недопустимые UUID/gid,
  enum, диапазоны и неправильные типы возвращают контролируемые ошибки.
- Пустая страница и отсутствие клиента различаются; большие gid остаются строками.
- Изолят, seed, depth=4 и null ratio сохраняются в карточках и графах.
- Усечение графа не ограничивает полные прямые связи; hidden соответствует totals.
- Некорректный Parquet, неполный multipart, повтор файла и превышение размера отклоняются.
- Публичный импорт synthetic не объявляет его официальным по числу строк.
- Одновременные запросы с одним idempotency key дают один run; разные ключи
  не создают два активных расчёта датасета. Два worker не захватывают один run.
- Потерянное задание переходит в failed; живой heartbeat не восстанавливается ошибочно.
- Полностью опубликованный bundle после сбоя до фиксации БД восстанавливается в succeeded.
- Потерявший владение worker не проходит publication guard.
- Неверный selection не меняет сохранённый список; порядок, дедупликация,
  лимит и изоляция run проверены. Обязательные CSV отдаются исходными байтами.
- Повреждение bundle даёт RESULT_INVALID, без подстановки старого run.
- Внутренняя ошибка не раскрывает сообщение исключения; request_id в заголовке и теле совпадает.

## Повторение

```powershell
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m pytest -q
docker compose build tests
docker compose run --rm tests
docker compose --profile backend up -d --build api worker
.\.venv\Scripts\python.exe scripts/smoke_backend.py --data data
```

Каждый HTTP smoke создаёт новый импорт/run и записывает в нём тестовый selection.
Приведённые run_id — факты этого рабочего окружения, не обязательные данные
репозитория. Новые runtime-файлы не включаются в Git. Числа runtime зависят от
машины и нагрузки; из них не следует обещание такой же задержки на любой машине.
