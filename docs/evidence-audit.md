Аудит рассчитан на нынешние шаблоны reporting.py: при изменении формата текста его парсер нужно обновить. Он не проверяет качество AML-классификации на независимой разметке и не заменяет смысловую оценку человека.

## Оценка понятности

Моя качественная оценка короткого CSV-evidence — **7/10**; вместе с текущей UI-карточкой — **8/10**. Это экспертное суждение о объяснении, не измеренная точность модели.

**Что хорошо:** короткие и конкретные числа, специализация текста под роль, сохранение seed/depth-оговорок, отсутствие утверждений о виновности. Why отделяет основание роли от основания приоритета. UI добавляет смысл роли, следующий шаг проверки и раскрываемую альтернативу.

**Что снижает оценку:**

1. Evidence перечисляет факты, но редко говорит, какой порог они прошли. Для consolidator/distributor можно добавить «4 отправителя ≥ порога 2» / «62 получателя ≥ порога 3».
2. Peripheral (1 495 клиентов) описывает потоки, но не объясняет отказ правил. Например, у `100000004041163100` выход 866 000 KZT и два получателя; без знания порога distributor=3 роль кажется неожиданной. UI частично снимает вопрос общим пояснением, но конкретные причины остаются в подробностях.
3. При близких ролях evidence звучит однозначно. У coordinator `100000008636603100` альтернатива distributor отстаёт лишь на 0,01468; этот факт стоит выносить ближе к основному объяснению.
4. «Прибл. посредничество 0.00283» трудно интерпретировать без порога или сравнения. «Контр.», «внешние соседи», seed/depth требуют знакомства с терминами.
5. Нет числа транзакций в коротком evidence, хотя оно участвует в score. Два клиента с одинаковым объёмом и разным количеством операций могут получить похожее объяснение.

## Примеры

Первый клиент Top — `100000003684369100`:

> Выход 62 контр.: 8588655.00 KZT; вход 3848436.00 KZT. Seed: вход неполон.

Это точное основание для роли distributor. Why добавляет «структура +0.314; объём +0.300». В UI те же вклады показаны в баллах из 100. Для жюри полезно объяснить, что 62 получателя превышают порог 3, а вход seed неполон.

Transit `100000008379273100`:

> Вход/выход: 36000.00/38000.00 KZT; отношение ≈1.06. Только наблюдаемые переводы ≥5000 KZT.

Корректно показывает отношение без заявления о быстром переводе денег. Временная причинность не доказана; UI это отдельно поясняет.

Coordinator `100000008636603100`:

> Прибл. посредничество 0.00283; внешних соседей 5; вход/выход 2/6 контр. Только наблюдаемые переводы ≥5000 KZT.

Факты точны, но читателю нужны значение метрики и оговорка о близкой альтернативе. Оба вопроса можно раскрыть в карточке; короткий CSV сам по себе объясняет их недостаточно.

## Рекомендации без изменения расчёта

Добавить пороги в evidence, конкретную причину peripheral и предупреждение о близкой альтернативе. Для основных ролей использовать понятные слова «отправители/получатели», для coordinator — краткое пояснение структурного посредничества. Изменения шаблонов требуют нового bundle, обновления тестов и аудита: старые опубликованные файлы вручную не редактировать.

В этом проходе такие изменения не вносились: пользователь запросил оценку качества и сохранение рабочих компонентов.
