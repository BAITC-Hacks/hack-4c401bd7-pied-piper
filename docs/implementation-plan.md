проверки, разбирает клиента и его связи, сохраняет выбор и скачивает результаты.
Охват — локальное рабочее место одного аналитика по профилю hackathon-v1.

## Как выполнять план

- Каждая строка — отдельная задача с проверяемым результатом; ID используется в PR
  и обсуждениях. Отметка выполнения допустима только после указанной проверки.
- «Зависит от» означает готовность к завершению интеграции. Frontend можно начинать
  на моках до соответствующих backend-задач, но закрывать интеграцию только на API.
- BE — backend, FE — frontend, QA — проверка и воспроизводимость. Это направления
  работы, а не назначенные исполнители и не команды запуска дополнительных агентов.
- Приведённые проверки — план тестирования. Этот документ не утверждает, что они
  уже пройдены. Существующее ядро не переписываем без конкретного дефекта.
- Сроки назначаются после оценки доступной команды. Полный список не является
  обещанием уложиться в оставшееся время хакатона.
- Первая контрольная точка — просмотр существующего результата через новый API.
  Затем импорт/расчёт и сохранение выбора. CLI и Streamlit сохраняются рабочими.

## Порядок работы и возможность параллельной разработки

Последовательность backend:

`A01 → A02/A03 → A04 → A05 → B → C → D → F`.

После A04 импорт C01 можно выполнять независимо от большинства read-endpoints.
После B03/B08 можно выполнять D, не ожидая полного worker. Это сокращает ожидание,
но не отменяет зависимости конкретных строк.

Последовательность frontend:

## Что отложено до завершения этого плана

- Пользователи, авторизация, роли сотрудников, совместное редактирование и полноценные дела.
- Универсальный CSV/Excel импорт, банковские интеграции, онлайн-потоки.
- AI-ассистент, внешнее обогащение, облачная инфраструктура.
- Новые аналитические алгоритмы. После M4 выбрать одну дополнительную возможность
  из ТЗ: оценка полноты, временные паттерны или устойчивость сети — с отдельным
  контрактом, объяснением ограничений и тестами.

Если времени недостаточно, остановиться на законченной контрольной точке и честно
обозначить объём. Нельзя заявлять готовый импорт, постоянное сохранение или API,
если демонстрация использует только моки.

## Общий критерий закрытия задачи

В итоговом сообщении/PR указать ID задачи, изменённое поведение, выполненную
проверку и результат. Для UI приложить скриншот. Для новой схемы хранения — способ
инициализации/миграции. Для ошибки или неполного пункта записать ограничение,
вместо отметки «готово». Коммиты не включают новые датасеты, runtime-базы,
сгенерированные результаты, кеши и виртуальные окружения.
