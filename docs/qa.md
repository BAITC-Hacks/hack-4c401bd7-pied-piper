# Приёмка результата и UI

Команды выполняются из корня. Основные зависимости и способы запуска — в [README](../README.md). Реальный набор уже включён в репозиторий; synthetic-пример проверяет интерфейс и протокол отдельно.

## Автоматическая проверка

Windows:

```powershell
.\make.cmd pipeline
.\make.cmd validate
.\make.cmd test
.\.venv\Scripts\python.exe scripts/audit_evidence.py --data data --out outputs
```

Linux/macOS: make pipeline, make validate, make test; для audit — .venv/bin/python. Docker:

```bash
docker compose build ui
docker compose up -d --no-build --pull never
docker compose run --rm validate
docker compose build tests
docker compose run --rm tests
```

Скрипт audit_evidence — отдельный локальный QA-инструмент, в runtime-образ не включён. Для аудита Docker-публикации нужно передать её файлы в доступный локальный каталог и указать --out; не считать локальный outputs/ тем же Docker volume.

Записать commit, run_id, Python/версии из run.json, stage_runtimes_seconds.total и вывод проверок. UUID и runtime меняются при каждом пересчёте. Полный pytest не оценивает accuracy AML-классификации.

## Ручной маршрут

1. Открыть http://localhost:3000, выбрать «Проверка клиентов», нажать клиента очереди.
2. Сверить evidence, приоритет и вклад каждого фактора. UI показывает priority×100; CSV хранит [0,1].
3. Найти три произвольных gid, включая поиск при несовместимых фильтрах.
4. Проверить boundary и изолированный seed из [демо](demo.md); предупреждения должны быть видимы.
5. Сверить суммы/количество прямых переводов с таблицами, проверить стрелки, 1–2 шага, drag/zoom/reset.
6. Открыть «Сеть и сообщества»: таблицы кластеров и компонент. Не путать ограничение графа с потерей данных.
7. Скачать три CSV через «Скачать результаты и проверить данные» и сравнить SHA256 с manifest того же run.
8. В «Сеть и сообщества» раскрыть «Устойчивость сети», переключить N=1/3/5/10. Сравнить два списка исключённых gid, число оставшихся узлов и затронутые суммы. Фильтры очереди не должны менять эксперимент; SHA256 CSV до/после должен совпадать. Убедиться, что предупреждение о неполноте модели видно.

Отдельные проверки симуляции: `.venv/Scripts/python.exe -m pytest -q tests/test_resilience.py tests/test_ui.py`. Покрыты разрыв моста, удаление листа без разобщения оставшихся пар, старые/новые изоляты, встречные рёбра и петля без двойного счёта суммы, большие gid и равенства, пустая сеть, полное исключение, сохранность входов и bundle, UI-переключатель и независимость от фильтров.

## Статус и границы

После добавления симуляции устойчивости: полный локальный pytest — **182 passed за 92,80 с**, Windows / Python 3.12, PYTHONUTF8=1. Единственное предупреждение — об устаревании HTTPX-адаптера Starlette TestClient. В набор входят 9 случаев расчёта устойчивости и новый UI-сценарий. Целевые тесты симуляции и UI после финальной правки таблицы — **13 passed за 1,59 с**. Дополнительно Streamlit AppTest открыл официальный run a4667554-02a0-4c8f-8d92-912065a14deb и переключил top-5/top-10 без ошибок. Расчёт top-5 занял около 0,04 с без загрузки/отрисовки. Docker и живой браузер в этом проходе заново не проверялись.

Текущий аудит evidence: [отчёт](evidence-audit.md). Исторические автоматические и браузерные проверки: [индекс](README.md). После следующих merge полный pytest нужно повторять; число тестов меняется.

Репетиция живого пятиминутного выступления в текущем проходе не выполнялась. Финальный запуск после клонирования на машине жюри отдельно не подтверждён. Зафиксированное ранее расхождение SHA256 старого локального bundle требует пересчёта или проверки доставки; нельзя отключать проверку хешей.
